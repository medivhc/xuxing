# autonomous-explore-loop — 自主探索循环

给一个长期目标，agent 自主循环推进。**核心分工：循环本身是规划者，不是执行者。**

- **规划者（本循环）**只做三件事：探索（搞清现状与未知）、规划（维护任务队列、决定下一步）、
  收结果（每轮先看各执行器回来的结果，再决定下一步行动）。
- **执行者**做所有具体的事：写代码、跑测试、查资料、问外部模型……执行者是外部程序/服务，
  如真机上的 opencode、nx-pipeline 的各 phase、浏览器自动化程序、子代理评审。
  规划者只负责**派发**（写清任务书、指定完成判定）和**验收**（按判定核对回传结果），不亲自下场干活。
- 执行是**异步**的：派发完就结束这一格，执行者跑完把结果写回结果收件箱；
  下一轮（或后续某一轮）规划者 harvest 结果，再决定下一步。队列里因此常有多个 `dispatched` 在飞。

## 探索 → 程序（本机制的复利来源）

遇到一类新的活，第一次由规划者亲自探索（试路径、踩坑、搞清怎么调用），
探索成功后**立刻抽象成一个可直接调用的程序**（脚本/skill/固定调用模板），登记进执行器注册表；
之后同类需求不再探索，直接派给这个程序。例如：第一次用浏览器操作 ChatGPT 网页版问问题（探索登录、
提问、取回答的路径），之后沉淀为 `ask-chatgpt` 程序，循环需要外部建议时异步调用它，结果回写收件箱。

## 文件布局（每个试点目标一份，放在该 goal 的工作区）

- `files/AUTOPILOT.md` — 目标章程：长期目标、退出标准、边界/护栏、循环节奏。用户可随时改。
- `files/QUEUE.md` — 任务队列（规划的事实来源）：每条任务必须有 id、状态、为什么做（证据）、
  完成判定、**执行器**、依赖、结果链接。没有完成判定或没指定执行者的任务不许进 ready。
- `files/EXECUTORS.md` — 执行器注册表：每个执行器的调用方式、异步结果回哪、已知限制（如并发锁）。
- `hidden_files/results/` — 结果收件箱：执行器回传的结果文件，一任务一文件，文件名含任务 id；
  规划者 harvest 后在队列里链接并标状态，未 harvest 的结果不得当作已知事实使用。
- `hidden_files/explorations/<date>-round<N>.md` — 每轮探索日志：探针输出、收了哪些结果、判断、队列变更、新沉淀的程序。
- `hidden_files/tools/` — 探针脚本（只读优先）与已抽象成型的可调用程序。

## 任务状态机

`proposed → ready → dispatched → done / blocked / dropped`
- proposed：探索产出，证据或执行器尚未落实。
- ready：证据已核、判定明确、执行器已指定，可派发。
- dispatched：已派给执行器、结果未回。规划者不等待、不轮询催促，靠收件箱和既有 watcher 感知完成。
- blocked：写清卡点与谁能解（用户拍板 / 执行器故障 / 前置任务）。
- done：结果已 harvest 且按完成判定验收通过，附结果链接。不许凭执行者自称完成就标 done。

## 单轮循环（每轮只推进一格）

1. **收结果**：先看收件箱有无新结果、既有 watcher/探针有无状态变化；逐条 harvest：
   对照完成判定验收，过 → done，不过 → 退回 ready 或转 blocked，并把验收结论写回队列。
2. **探**：跑探针拿真实状态（二手状态文件与一手证据冲突时以一手为准，漂移本身入队）。
   遇到新类型的活，先探索路径，成功后抽象成程序登记注册表（见上节）。
3. **判与入队**：对照退出标准算差距；新任务带证据、判定、执行器入队；拆分 ≤2 层；每轮新增 ≤5 条。
4. **派发一格**：取 ready 队首，写任务书派给其执行器，标 dispatched。派发即完成本轮"行"的部分，
   不在本轮内等结果。需要用户批准的动作（新批次开工、未批准的 fix 方案、不可逆/对外/花钱）不派发，转 blocked 报告用户。
5. **报**：静默为默认。只有三种情况报用户：需要拍板、blocked、里程碑 done。

## 护栏

- 规划者不亲自执行具体任务（写业务代码、长跑测试、批量操作都不行）；亲自做的只有探索性小实验
  （为抽象程序而做的、分钟级的）和只读探针。
- 每轮最多：派发 1 格、新增任务 ≤5 条。
- 连续 2 轮无新结果且队列无 ready → 停循环并报用户（防空转）。
- 章程与队列冲突时以章程为准，冲突入队为 decision 任务。
- 评审独立性、TDD 轮次上限等既有铁律继续有效；执行器内部的规矩（如 opencode 串行、CDP 独立 profile）记在注册表里，派发前必查。
