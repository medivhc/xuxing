# 续行工程标准（ENGINEERING）

> 总则（用户 2026-10-24 授权）：质量、门禁、复用、文档、卫生按最优最优雅标准执行，由协调者维护本文件；与 VISION.md 冲突时以愿景为准。

## 1. 质量门禁（任何代码进主线必经，全自动、不跳步）
冻结 spec → 实现 → 测试真跑（证据归档）→ 独立评审（异模型、盲评）→ fix → 复审 → 合入。任一环的"通过"必须有可复查证据（测试输出原文数字、commit hash、报告文件），口头声称不算。环境跑不了的测试（如沙箱无 PG）必须显式标注未跑项，并由 CI 环境补跑拿证据，不许静默略过。

## 2. 复用优先（写新代码前先找）
先查三处：仓库内已有实现 → 已装 skill/工具（farm 派发器、watcher、nx-* 流水线）→ 成熟开源库。重复出现第二次的动作固化成程序/skill（见迭代四件套）。不为一次性需求造框架，不为框架而框架。

## 3. 文档同行（代码与文档同批交付；正本在仓库）
- 项目的要求、进度、决策、标准**正本一律进项目仓库** `docs/`（VISION / ENGINEERING / DECISIONS / STATUS），协调者工作区只留工作副本与指针；同一事实只有一个正本，文档间只引用、不复制。
- 决策 → `docs/DECISIONS.md`（编号 D 续编，附理由与备选）；经验与坑 → 平台 NOTES / 项目 PITFALLS；打法 → skill（唯一入口）。
- **强制一致（CI docs-check，不过即红）**：① 文档内相对引用必须可达；② `docs/STATUS.md` 头部 `based_on` 必须是当前 HEAD 的祖先且落后 ≤10 个提交（进度必须与代码同行更新）；③ DECISIONS 编号连续无重复、被代码注释引用的编号必须存在；④ 可由代码/测试生成的数字（测试计数、覆盖矩阵）不手写，由脚本生成后提交。
- 状态 → 仓库 STATUS 是对外唯一真相；协调者 QUEUE/CHAIN 与之定期对账，不一致即漂移、先对账再派活。

## 4. 分支与环境卫生（临时物用完即清）
- 执行器分支统一 `qoder/` 前缀；**合入后 24h 内删除远端分支**，被拒收的分支在报告归档后删除。
- 云端会话 harvest 完成后归档（watcher archived 标记）并关闭 tab，不留僵尸标签页。
- worktree 一轨一目录、结束即 `git worktree remove`；临时文件进 `/tmp` 或 hidden_files 并注明用途，跨轮不留无主文件。
- 凭据零落盘：token 只进任务指令，存档回显一经发现立即脱敏。
- 每轮迭代收尾做一次卫生扫除：分支列表、会话列表、队列状态三方对账。

## 5. 优雅的判据（拿不准时按此裁量）
- 同一事实只有一个来源（事件流之于产品、CHAIN 之于进度、skill 之于打法）。
- 自动化必须带自验：看门狗修完要验、派发器发出要核、推送完要读回——"报告成功"永远不等于"已经成功"。
- 失败大声、状态诚实：跑不了就写跑不了，跳过就写跳过；宁可留一个显眼的未完成，不留一个隐形的假完成。
